[06 §12.7](../spec/06-web.md#127-browser-support-and-manual-checklist); platforms from

**n/a** – does not apply; **open – manual** – needs a real device and a person (not yet done).

## 3. Procedure per manual row

> Superseded for real devices by [prf-devices.md](prf-devices.md) (KOR-54): since rules E-12 and E-13 a
> registration refuses a passkey without PRF and shows no recovery code, so steps 1, 2 and 6 below no longer match the
> product. The steps stay as the record of the 0.1.0 procedure.

Use a test hub of this release (not production) and a platform invitation per row
([../runbooks/platform-root-key.md](../runbooks/platform-root-key.md), short lifetime). A runner device or the
test topology must serve the private organization so that a task can start.

1. **Registration:** open the invitation link, enter a name, "Create passkey" with the provider of the row, unlock,
   note the recovery code and confirm it. Pass: the private organization opens. If the "Remember this browser" offer
   appears, the passkey delivered no PRF – record that in the PRF column and decline the offer.
2. **PRF:** Settings → Passkeys. Pass (PRF supported): the passkey shows "Unlocks your encryption keys". Record
   "no PRF" when it shows "Cannot unlock your encryption keys (no PRF)" – this is not a failure of the app but the
   finding the matrix is for.
3. **Login:** sign out, sign in with the passkey. Pass: with PRF the organization opens after one gesture; without
   PRF the page offers the recovery code and unlocks with it.
4. **Countdown:** send a first prompt from the home screen. Pass: the countdown shows digits ≤ 10, the steps fill in
   with times, then "Ready in … s"; no spinner; on a phone the composer stays above the keyboard.
5. **Terminal:** open the session's terminal. Pass: the read-only label, output visible, Follow/History work, typing
   into the terminal sends nothing; on a phone horizontal scroll and pinch-zoom on the terminal only.
6. **Recovery:** sign out, delete the passkey in the provider (or use another browser profile), "Use recovery code",
   enter the code, create a new passkey. Pass: a new recovery code is shown and must be confirmed; the organization
   opens; the old code is refused afterwards.

Write every deviation below with steps, screenshots (no codes or keys in them) and the browser console output.

## 5. Residual risk

Until the manual rows are checked, PRF support of real passkey providers is **unverified** (ADR-006, AUD-01 B-12):
users of a provider without PRF can work only with the recovery code or a remembered browser. The check needs a person
(listed as open in `docs/platform/acceptance/FINAL.md`).
