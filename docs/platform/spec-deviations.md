# As-built register: implementation vs. specification

Status: This register records, per specification document (`docs/platform/spec/00-overview.md` … `10-work-packages.md`) and per ADR, where the implementation on the integration branch refines, extends or deviates from the text. The specification text stays the design; it is not rewritten to match every implementation detail. Each row names the specification place, states what is built (with code evidence), and the work-package decision that settled it. "Handling" is one of: `spec updated` (the specification text was changed by DOC-01 or, for the correction packages KOR-01 … KOR-11, ATS-03, DR-01 and LVT-01, by KOR-12), `as built` (refinement or extension; the implementation is binding, the specification text is kept), `deviation` (conscious deviation, accepted with the stated reason) or `open defect` (the implementation is wrong and has to be corrected; the audit item or correction package is named where one exists).

State: integration branches of 2026-11-22 (agent `a8ffee50`, agent-core `524c716`, plus KOR-01 A-02, KOR-04 A-07, KOR-06, KOR-07 from agent-core `0a04761`), all work-package decisions up to SCN-08, swept by DOC-01; the correction packages KOR-01 … KOR-11, ATS-03, DR-01 and LVT-01 swept by KOR-12 (integration branches of 2026-11-23). Later packages add their rows here when they change a specified behaviour.

Repository prefixes: `agent:` (runner, guest, doubles, images) and `agent-core:` (hub, web, contracts, E2E) precede paths. Decision references read `agent: decisions/RUN-01.md #20`, meaning item 20 of `docs/platform/decisions/RUN-01.md` in that repository. ADRs exist in both repositories and are cited by number only.
