## Open risks carried into M2

- GitHub Actions still create no runs for the integration branches; the local gates stay binding.
- The hub's anonymous limit (30/min per source) is tight for many onboardings from one address (E2E suites, a shared
  NAT); the suites space onboardings, the product behaviour is unchanged.
- Gates of `agent` and `agent-core` of the same package share one port range: running them at the same time fails
  the port pre-check or a bind (seen during this package); run them one after the other.
- The hermetic E2E run cannot build a missing golden image (egress refused): acceptance and scenario packages ensure
  the golden cache first (`tools/wp/golden-cache.sh`).
- E2E-11 still reads the VM assignment from the runner store; it can now assert the hub's `session.vm_id` (SCN-03+).
- `pollinate.service`/`ubuntu-advantage.service` are active in the golden image (no egress observed in any run).
