## `tasks/title.json` (new)

`06-web.md` section 4.2 requires a vector-tested title derivation, and the runner checks `task.set_title` titles with
the same rule. The specification says "Unicode whitespace" and "first non-empty line" without naming the character
sets, which two implementations (TypeScript and Python) would otherwise choose differently (`\s` in JavaScript
includes U+FEFF, Python's `str.isspace` includes U+001C-U+001F, `str.splitlines` splits at U+001C-U+001E). The file
fixes them: whitespace is the Unicode `White_Space` property, line breaks are CR LF, LF, CR, U+000B, U+000C, U+0085,
U+2028 and U+2029; a line counts when it is not empty after collapsing; the cut is 79 code points + `…` above 80.

The file is hand-maintained data outside `vectors/`: every file in `vectors/` must be regenerated by the crypto
generators of both repositories (`agent_hub.crypto.vectors`, `agent_runner.crypto.vectors`), and titles are no
crypto (the hub never sees them). The expected titles were produced by an independent Python implementation and
are reproduced by `web/src/core/tasks/title.ts` (`web/tests/core/crypto/vectors.test.ts`). The layout table of
`README.md` lists the file.

## Passkey creation-option fixtures: user handle = bytes of `user_id` (defect)

`api/objects.json#/$defs/creation_options` says "user handle = the 16 bytes of user_id", and the web client now
refuses options whose `user.id` is not the 16 bytes of `user.name` (= `user_id`). The fixtures of
`fixtures/api/passkeys-register-begin.response/` and `fixtures/api/recovery-finish.response/` (valid and invalid)
carried the placeholder `Hh4e…` (16 × 0x1e) next to `user_id` `0193000a-0000-7000-8000-00000000000a`; they now carry
`AZMACgAAcACAAAAAAAAACg`, the bytes of that UUID. No schema changes; the invalid fixtures stay invalid for their
stated reason.
