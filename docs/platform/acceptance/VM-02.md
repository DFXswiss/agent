# VM-02 acceptance evidence (warm pool, clone fallback, VM lifecycle, capacity, guestlink)

## Unit and integration tests (`make platform-ci`)
- `tests/platform/runner/vm/test_pool.py`, `test_lifecycle.py`, `test_capacity.py`, `test_vm_tasks.py`,
  `test_pool_cli.py`; `tests/platform/runner/guestlink/test_client.py`, `test_reader.py`.
- Lima is injected (`FakeLimactl` with recorded Lima 2.3.0 output, VM-01); every started fake instance runs a real
  GST-01 guest control process on `<instance>/sock/agent-guest.sock` with the token from the Lima parameter; the store
  is a real PostgreSQL database.
- Covered: pool fill (clone, token parameter, parameter blanked in `lima.yaml`, health, self-test), retry with a new
  name and `vm_start_failed`, health timeout, self-test failure/timeout, refill limits (pool size, 2 in parallel,
  free slots), take/skip broken pool VM, purge of a retired golden; `ensure_vm` order (running, restart, golden
  replacement, suspended session keeps the golden, pool, clone), two sessions of one workgroup ⇒ one VM, unique
  index; capacity formulas, pool VM given up, LRU stop, `capacity_exhausted`, no deadlock on a held lock; idle stop;
  health failures (restart once, then stop); deletion; startup reconciliation; outbox `vm_state` and heartbeat fields;
  `pool status`; uninstall cleaner; guest client (all endpoints, error classes), journal reader and cursor.
- Coverage of `agent_runner.vm` and `agent_runner.guestlink`: 100 % lines and branches.
